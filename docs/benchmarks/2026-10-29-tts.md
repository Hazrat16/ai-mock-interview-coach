## Memory
| Situation | Piper memory |
|---|---|
| One voice, question-sized requests (normal use) | ~290 MB |
| Each additional voice used (e.g. trying voices in Settings) | +~230 MB, kept until Piper restarts |
| All four voices loaded | ~1.05 GB |
| Benchmark: whole 13 s texts with ljspeech-high | peak 1.43 GB |

With the first 1 GB limit, the benchmark got Piper OOM-killed (kernel log: memory cgroup out of memory). The limit is now 2 GB (`PIPER_MEM_LIMIT`); it is a cap, not a reservation. If it is ever hit, Docker restarts Piper.

## Robustness (measured)
- Piper process killed: Docker restarted it in ~4 s (`restart: on-failure:5`). A TTS request sent right after the kill still succeeded (3.1 s): the app retries an unreachable Piper for ~6 s.
- Piper stopped: the app answers 503 "Piper is not reachable … Start it with: make deps-up" after ~6 s, health shows "Not running", and the interview text stays on screen with a Retry button.
- Piper silently uses its default voice for an unknown voice name, so the app only accepts voices from its catalog (400 otherwise).

## Notes for later milestones
- M7: the acknowledgment ("Thank you.") is cached and could be played immediately on submit, while the LLM decides, to shorten the silence.
