# Speech-to-text (M6), 2026-10-29

whisper.cpp **v1.9.5** (MIT) built in Docker (`docker/whisper.Dockerfile`: static binary, `GGML_NATIVE` → AVX2 + AVX-VNNI on the i7-1355U, OpenMP), 8 threads, `-l en -nlp -sns`, temperature 0. Models from `huggingface.co/ggerganov/whisper.cpp` (MIT) at commit `5359861c`, SHA-256 checked (`shared/sttModels.ts`). Re-run with `make bench-stt`.

## Loopback test (Piper speaks, Whisper transcribes)
12 interview-style answers with numbers and tool names (130 s), read by two Piper voices (ljspeech-medium, joe-medium); plus a 36 s clip of three answers joined. WER after normalization (`shared/text/wer.ts`: case, punctuation, "40" = "forty"). RTF = transcription time / audio length.

| Model | Size | Loopback WER | RTF | 36 s clip | Memory |
|---|---|---|---|---|---|
| **base.en** | 148 MB | **5.1%** | 0.137 | **4.5 s** (WER 10.8%) | ~245 MB |
| base.en-q5_1 | 60 MB | 5.4% | **0.097** | **2.8 s** (WER 9.8%) | ~160 MB |
| small.en | 488 MB | 5.4% | 0.481 | 14.9 s (WER 11.8%) | ~640 MB |
| small.en-q5_1 | 190 MB | 5.9% | 0.356 | 10.3 s (WER 13.7%) | ~350 MB |

Most remaining errors come from Piper's pronunciation of terms, not from Whisper: "PostgreSQL" → "poster SQL", "Redis" → "release", "read-heavy" → "red heavy", "here own" → "hear own". All four models make the same ones, so **synthetic speech cannot tell the models apart; your own recordings decide** (below).

**Passing the question as Whisper's `prompt` made results slightly worse** (base.en 5.1% → 5.4%, small.en 5.4% → 6.2%), so the interview does not send it. The API keeps the option (`/api/stt?prompt=`) for later experiments, e.g. a vocabulary list.

## Through the app
- Browser pipeline without the microphone (Piper 22.05 kHz → the web downsampler → 16 kHz WAV → `POST /api/stt`): 1.2 s for 6.6 s of speech.
- 3 s of near-silence → empty answer (no invented "Thank you."), as required for "Sorry, I didn't catch that" in M7.
- whisper-server killed: Docker restarted it, and a request sent right after still succeeded (2.0 s).
- No audio file is written by `/api/stt` (whisper-server runs without `--convert`, which would use temp files; checked by a test and on disk).

## Own recordings
Built-in laptop microphone (`sof-hda-dsp` digital mic array), browser voice processing on (Chrome's default), 4 interview-style sentences each run.

| Model | Run 1 WER | Run 2 WER | RTF (run 2) |
|---|---|---|---|
| **base.en** | 37.5% | **9.9%** | 0.114 |
| base.en-q5_1 | 42.5% | 11.1% | 0.085 |
| small.en | 35.0% | 8.8% | 0.400 |
| small.en-q5_1 | 35.0% | 8.8% | 0.307 |

Run 1 scores were from before the fairer WER normalization ("HashMap" = "hash map", "ms" = "milliseconds"), which explains only a few points of the drop.

**Correction to the run-1 diagnosis.** After run 1 the recordings were called "muffled": only 0.5-1.5% of their energy is above 2 kHz, against 9.5% for Piper's voice. Run 2 used the **same microphone and setting** with the same spectrum (0.7-2.3% above 2 kHz, 54-70% below 300 Hz), and reached 9.9%. So the spectrum is just how this laptop mic sounds, not the cause; the first takes most likely differed in delivery (distance, pace, first attempts). Ruled out along the way: the app's downsampler (flat to 6 kHz) and the ALSA mixer (Dmic0 +8 dB, nothing muted). The benchmark no longer labels recordings "muffled"; the numbers remain for comparing setups.

Remaining errors are product names and numbers ("API" → "APA/EPA", "Redis" → "radis", "one hundred and twenty" → "120" with the unit dropped). These matter little for interview feedback, which judges content.

## Decision
**`base.en` is the speech-to-text model** (`WHISPER_MODEL=ggml-base.en.bin`, unchanged).
- It meets both targets: 9.9% WER on your voice (≤ 15%) and a 36 s answer in 4.3 s (≤ 5 s).
- `small.en` is only 1.1 points better but 3.5× slower (a 36 s answer takes 14 s), and it fails the speed target.
- `base.en-q5_1` (11.1%, 30% faster) is the fallback if M7 turns out CPU-bound.
- The question is not sent as Whisper's prompt (it made loopback results worse in both runs).
- Browser voice processing stays **on**: the interviewer plays through the laptop speakers (D3, revised 2026-10-30), so echo cancellation is needed.

## Notes for M7
- Transcribe each speech segment while you are still talking; only the last one is pending at the end (RTF ~0.14 means a 10 s segment takes ~1.4 s).
- The thresholds used to drop segments: `no_speech_prob > 0.6`, `avg_logprob < -1.0`, known hallucination phrases (`server/src/speech/transcript.ts`). Re-check them against real microphone noise.
